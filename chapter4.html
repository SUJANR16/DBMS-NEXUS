SLIDES 02–05

1. Joined Relations & Natural Join

• Join Operations: Take two relations and return another relation as a result.
• Natural Join: Matches tuples with the same values for all common attributes and retains only one copy of each common column.
• Multi-Table Natural Joins: Sequential evaluation syntax: select A1, A2, ... from r1 natural join r2 natural join .. natural join rn where P;

select name, course_id
from student natural join takes;

3. Outer Joins (Left, Right, Full) & Relational Algebra Notations

• Outer Join: An extension of the join operation that avoids loss of information by adding tuples from one relation that do not match tuples in the other relation, padding missing attributes with null.
• Left Outer Join (course ⟕ prereq) [Slide 12]: Preserves all tuples from left relation (course).
• Right Outer Join (course ⟖ prereq) [Slide 13]: Preserves all tuples from right relation (prereq).
• Full Outer Join (course ⟗ prereq) [Slide 14]: Preserves all tuples from both relations.

SLIDES 19–28

5. Views, Dependencies, Materialized Views & View Updates

• View: A virtual relation that is not part of the conceptual model but made visible to users. Used to hide sensitive attributes (e.g. salary).
• Syntax: create view v as <query expression>;
• Dependencies [Slides 22 & 23]: $v_1$ depends directly on $v_2$ if $v_2$ is in the definition of $v_1$. Recursive if $v$ depends on itself.
• Materialized Views [Slide 24]: Views that are physically stored on disk when defined. Must be maintained (refreshed) when base tables update.
• Updatable View Criteria [Slide 28]:
  1. The from clause has only one database relation.
  2. The select clause contains only attribute names (no expressions, aggregates, or distinct).
  3. Any attribute not listed in select can be set to null.
  4. The query does not have a group by or having clause.

create view faculty as
  select ID, name, dept_name
  from instructor;
SLIDES 29–34

6. Transactions & Single-Relation Integrity Constraints

• Transactions [Slide 29]: Sequence of query/update statements executed as an atomic unit. Ends with commit work (permanent) or rollback work (undone).
• Integrity Constraints [Slides 30–33]: Guard against accidental damage and preserve data consistency.
  - not null: Prohibits null values (e.g., name varchar(20) not null).
  - primary key (A1..An): Uniquely identifies tuples (implicitly not null).
  - unique (A1..An): Specifies candidate keys (candidate keys are permitted to be null, in contrast to primary keys).
  - check (P): Validates predicate condition $P$ on every tuple (e.g., check (semester in ('Fall', 'Winter', 'Spring', 'Summer'))).

SLIDES 35–40

7. Referential Integrity, Cascading Actions & Assertions

• Referential Integrity [Slides 35 & 36]: Foreign key in referencing relation must match the primary key of the referenced relation.
• Cascading Actions [Slide 37]: When a constraint is violated on delete/update, SQL allows automated cascades instead of rejection:
  - on delete cascade / on update cascade: Deletes/updates child rows automatically.
  - on delete set null / on delete set default: Replaces references with null or default value.
• Integrity Violations During Transactions [Slide 38]: Handled by inserting parents before children, using null initial values, or deferring constraint checking to transaction end.
• Complex Check Conditions [Slide 39]: check (time_slot_id in (select time_slot_id from time_slot)).
• Assertions [Slide 40]: Predicates expressing global conditions the entire database must always satisfy:
  create assertion <assertion-name> check (<predicate>);

create table course (
  course_id varchar(8),
  dept_name varchar(20),
  primary key (course_id),
  foreign key (dept_name) references department
    on delete cascade
    on update cascade
);
SLIDES 41–44

8. Built-in Data Types, Large Objects, User-Defined Types & Domains

• Temporal Types [Slide 41]:
  - date: 4-digit year, month, day (e.g., date '2005-7-27').
  - time: Hours, minutes, seconds (e.g., time '09:00:30').
  - timestamp: Combination of date plus time of day.
  - interval: Period of time (e.g., interval '1' day). Subtracting timestamps produces an interval.
• Large-Object Types (LOBs) [Slide 42]: Stored as objects where queries return a pointer rather than the large data itself:
  - blob: Binary Large Object (uninterpreted binary data like photos, videos, CAD files).
  - clob: Character Large Object (large collections of character data).
• User-Defined Types [Slide 43]: Created using create type construct (e.g., create type Dollars as numeric(12,2) final;).
• User-Defined Domains [Slide 44]: Created using create domain construct in SQL-92. Domains can have constraints (like not null or check) specified directly on them:

create domain person_name char(20) not null;

create domain degree_level varchar(10)
  constraint degree_level_test
  check (value in ('Bachelors', 'Masters', 'Doctorate'));
SLIDES 45 & 46

9. Index Creation & Query Optimization

• Purpose: Many queries reference only a small proportion of records in a table. It is inefficient for the system to read every record to find records with a particular value.
• Index: A data structure on an attribute that allows the database system to find matching tuples efficiently without scanning all records.
• Command Syntax: create index <name> on <relation-name> (attribute);

create index studentID_index on student(ID);

-- The following query executes efficiently using the index:
select * from student where ID = '12345';
SLIDES 47–55

10. Authorization, Privileges, View Security, Roles & Transfer

• Privileges [Slides 47 & 48]: select, insert, update, delete, index, resources, alteration, drop.
• Authorization on Views [Slide 54]: A user granted access on a view (e.g. geo_staff on geo_instructor) does not need permission on the underlying table (instructor). The creator of the view must have permissions on the underlying table.
• References Privilege [Slide 55]: grant reference (dept_name) on department to Mariano; allows Mariano to create foreign keys referencing department.
• Transfer of Privileges (with grant option) [Slide 55]: Allows a user to grant the privilege to other users.
• Revocation Variants [Slide 55]:
  - revoke select on department from Amit, Satoshi cascade; (Cascades revoke to dependent grantees).
  - revoke select on department from Amit, Satoshi restrict; (Fails if cascade is required).
• Roles [Slides 52 & 53]: create role instructor; → grant instructor to dean; (creates hierarchical privilege chains).

grant select on department to Amit with grant option;
grant reference (dept_name) on department to Mariano;
revoke select on department from Amit, Satoshi cascade;

1. Outer Join Relational Algebra Operators:

• Left Outer Join: $r \leftouterjoin s$

2. Updatable View Criteria:

Single table in FROM + No aggregates/expressions/distinct + No GROUP BY/HAVING + Unselected columns allow NULL.

3. Candidate Key vs Primary Key Nullability:

PRIMARY KEY → Never permits NULL.
UNIQUE (Candidate Key) → Permitted to contain NULL values unless explicitly declared NOT NULL.

4. Authorization Transfer & Revoke Syntax:

GRANT <priv> ON <rel> TO <user> WITH GRANT OPTION;
REVOKE <priv> ON <rel> FROM <user> [CASCADE | RESTRICT];
