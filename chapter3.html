SLIDE 03

1. Overview of SQL Parts

• Data-Manipulation Language (DML): Provides the ability to query information from the database and to insert tuples into, delete tuples from, and modify tuples in the database.
• Integrity: The DDL includes commands for specifying integrity constraints.
• View Definition: The DDL includes commands for defining views.
• Transaction Control: Includes commands for specifying the beginning and ending of transactions.
• Embedded SQL and Dynamic SQL: Define how SQL statements can be embedded within general-purpose programming languages.
• Authorization: Includes commands for specifying access rights to relations and views.

SLIDES 04 & 05

2. Data Definition Language (DDL) & Domain Types

The SQL data-definition language (DDL) allows specification of the schema for each relation, domain types, integrity constraints, indices, security/authorization, and physical storage on disk.

char(n)

Fixed length character string, with user-specified length $n$.

varchar(n)

Variable length character strings, with user-specified maximum length $n$.

int / smallint

Integer and small integer (finite subsets of integers with machine-dependent precision).

numeric(p, d)

Fixed point number with precision $p$ digits and $d$ digits to right of decimal (e.g., numeric(3,1) allows 44.5, but not 444.5 or 0.32).

real / double precision / float(n)

Floating point and double-precision floating point numbers with at least $n$ digits.

SLIDES 06–09

3. Create Table Construct & Integrity Constraints

• primary key ($A_1, \dots, A_n$): Attributes automatically required to be not null and unique.
• foreign key ($A_m, \dots, A_n$) references $r$: Requires attribute values to correspond to the primary key of table $r$.
• not null: Prohibits null values from being stored for the attribute.

create table instructor (
  ID char(5),
  name varchar(20) not null,
  dept_name varchar(20),
  salary numeric(8,2),
  primary key (ID),
  foreign key (dept_name) references department
);
create table student (
  ID varchar(5),
  name varchar(20) not null,
  dept_name varchar(20),
  tot_cred numeric(3,0),
  primary key (ID),
  foreign key (dept_name) references department
);
SLIDE 10

4. Basic Table Modifications: Insert, Delete, Drop & Alter

• Insert: insert into instructor values ('10211', 'Smith', 'Biology', 66000);
• Delete: Removes all tuples from relation while retaining schema: delete from student;
• Drop Table: Completely removes tuples and schema definition from database: drop table r;
• Alter Table (Add Attribute): alter table r add A D; (All existing tuples are assigned null for the new attribute).
• Alter Table (Drop Attribute): alter table r drop A; (Dropping attributes is unsupported on many engines).

SLIDES 11–18

5. Basic Query Structure (select, from, where)

A typical SQL query has the form:
select A1, A2, ..., An from r1, r2, ..., rm where P; (The result of an SQL query is always a relation).
• select clause: Corresponds to relational algebra projection $\Pi$. Case insensitive (Name ≡ NAME ≡ name).
• distinct vs all: select distinct dept_name from instructor; forces duplicate elimination; all retains duplicates.
• Asterisk (*): Denotes all attributes: select * from instructor;
• Literals & Arithmetic: select '437' as FOO; or arithmetic: select ID, name, salary/12 as monthly_salary from instructor;
• where clause: Corresponds to relational algebra selection $\sigma$. Connectives: and, or, not; operators: <, <=, >, >=, =, <>.
• from clause: Corresponds to relational algebra Cartesian product $\times$.

SLIDES 19 & 20

6. Rename Operation (as) & Self Joins

• Rename Clause (as): Renames relations and attributes using old-name as new-name (keyword as is optional).
• Self-Join (Comparing a table with itself): Find instructors earning more than some instructor in 'Comp. Sci.':

select distinct T.name
from instructor as T, instructor as S
where T.salary > S.salary and S.dept_name = 'Comp. Sci.';
SLIDES 21–24

7. String Operations, Ordering Displays & Between Predicates

• String Matching (like): '%' matches any substring; '_' matches any single character. Escape wildcard using escape '\'.
• Ordering (order by): desc for descending, asc for ascending (default). Supports sorting by multiple attributes.
• Between Operator: where salary between 90000 and 100000 ($\ge 90000$ and $\le 100000$).
• Tuple Comparison: where (instructor.ID, dept_name) = (teaches.ID, 'Biology');

SLIDES 25 & 26

8. Set Operations: union, intersect, except

• union (in Fall 2017 or Spring 2018), intersect (in Fall 2017 and Spring 2018), except (in Fall 2017 but not Spring 2018).
• Standard set operations automatically eliminate duplicates. Use union all, intersect all, and except all to retain all duplicates.

SLIDES 27 & 28

9. Null Values & Three-Valued Logic

• Arithmetic with null evaluates to null (5 + null → null).
• Comparisons with null evaluate to unknown (5 < null, null = null).
• Boolean Logic: (unknown OR true) = true, (unknown AND false) = false, (NOT unknown) = unknown.
• Where clause filters out any row where predicate evaluates to unknown (treated as false).

SLIDES 29–33

10. Aggregate Functions, GROUP BY & HAVING Clause

• Functions: avg, min, max, sum, count. All ignore NULLs except count(*).
• Grouping Rule: Attributes in select clause outside aggregate functions must appear in group by list.
• HAVING vs WHERE: where filters individual rows before group formation; having filters aggregated groups after formation.

select dept_name, avg (salary) as avg_salary
from instructor
group by dept_name
having avg (salary) > 42000;
SLIDES 34–40

11. Nested Subqueries: Set Membership (in) & Set Comparisons (some, all)

• Set Membership (in / not in): Tests whether a value belongs to the subquery result set.
• Definition of "some" Clause [Slides 37 & 38]: $F \text{ } \langle\text{comp}\rangle \text{ } \mathbf{some} \text{ } r \iff \exists t \in r \text{ such that } (F \text{ } \langle\text{comp}\rangle \text{ } t)$.
  - (= some) ≡ in, but (≠ some) ≠ not in.
• Definition of "all" Clause [Slides 39 & 40]: $F \text{ } \langle\text{comp}\rangle \text{ } \mathbf{all} \text{ } r \iff \forall t \in r \text{ } (F \text{ } \langle\text{comp}\rangle \text{ } t)$.
  - (≠ all) ≡ not in, but (= all) ≠ in.

select name
from instructor
where salary > all (select salary from instructor where dept_name = 'Biology');
SLIDES 41–47

12. Advanced Subqueries (exists, unique, from-clause & with-clause)

• Empty Relations (exists / not exists) [Slides 41–43]: Tests if subquery is non-empty ($\mathbf{exists} \text{ } r \iff r \ne \emptyset$).
  - Correlated Subqueries: Inner query references correlation variables (e.g., S.course_id = T.course_id) from outer query.
  - Set Containment ($X \subseteq Y \iff X - Y = \emptyset$): Tested using not exists (X except Y).
• Uniqueness Test (unique) [Slide 44]: Evaluates to true if subquery contains no duplicate tuples.
• Subqueries in the FROM Clause [Slide 45]: Subquery expression placed directly in from clause without requiring a having clause.
• WITH Clause (Temporary Relations) [Slides 46 & 47]: Defines temporary views whose definitions are available only to the executing query.

with dept_total (dept_name, value) as (
  select dept_name, sum(salary) from instructor group by dept_name
),
dept_total_avg(value) as (
  select avg(value) from dept_total
)
select dept_name
from dept_total, dept_total_avg
where dept_total.value > dept_total_avg.value;
SLIDES 48–57

13. Scalar Subqueries & Full Database Modifications

• Scalar Subquery [Slide 48]: Used where a single value is expected. Returns a runtime error if the subquery returns more than one tuple.
• Deletions [Slides 50 & 51]: Can contain nested subqueries (e.g., delete from instructor where salary < (select avg(salary) from instructor);). SQL computes avg(salary) first and identifies all tuples to delete before performing deletions without recomputing.
• Insertions with Subqueries [Slides 52 & 53]: insert into instructor select ID, name, dept_name, 18000 from student where dept_name = 'Music' and total_cred > 144; (Evaluated fully before insertion).
• Updates with Scalar Subqueries & CASE [Slides 54–57]: Avoid order-dependent errors when updating values by using CASE statements:

update instructor
set salary = case
  when salary <= 100000 then salary * 1.05
  else salary * 1.03
end;
update student S
set tot_cred = (
  select case
    when sum(credits) is not null then sum(credits)
    else 0
  end
  from takes, course
  where takes.course_id = course.course_id
    and S.ID = takes.ID
    and takes.grade <> 'F'
    and takes.grade is not null
);
