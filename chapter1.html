SLIDE 03

1. What is a Database Management System (DBMS)?

A DBMS contains information about a particular enterprise[cite: 11]. It is a collection of interrelated data combined with a set of programs to access that data in an environment that is both convenient and efficient to use[cite: 11].

Highly Valuable: Mission-critical operational records[cite: 11].
Relatively Large: Terabytes to petabytes of enterprise data[cite: 11].
Multi-User: Accessed by multiple users and programs concurrently[cite: 11].

SLIDES 06, 07 & 08

3. Purpose of Database Systems (File Processing Pitfalls)

Storage & Access Limitations

• Data Redundancy & Inconsistency: Data stored in multiple file formats causes duplication and mismatched records upon partial updates[cite: 11].
• Difficulty in Accessing Data: Requires developing a brand-new program for every ad-hoc query[cite: 11].
• Data Isolation: Data scattered in multiple files makes writing retrieval tools tedious[cite: 11].
• Integrity Problems: Constraints (e.g., account balance > 0) are buried in application code rather than stated explicitly and centrally[cite: 11].

Transaction & Security Failures

• Atomicity of Updates: Failures leave the DB inconsistent with partial updates. Fund transfers must execute completely or not happen at all[cite: 11].
• Concurrent Access Anomalies: Uncontrolled concurrent access leads to inconsistency. Example: Two users reading balance $100 and withdrawing $50 simultaneously[cite: 11]!
• Security Problems: Inability to provide fine-grained user access to some, but not all, data[cite: 11].

5. View of Data, Levels of Abstraction & Data Independence

HIGHEST LEVEL

View Level (External)

Application programs hide data type details and conceal sensitive columns (like salary) for security[cite: 11].

MIDDLE LEVEL

Logical Level (Conceptual)

Describes what data is stored in the database and the relationships among those records[cite: 11].

LOWEST LEVEL

Physical Level (Internal)

Describes how a record (e.g., instructor bytes, pointers) is actually stored on disk hardware[cite: 11].

Figure: An Architecture for a Database System (Levels of Abstraction) [Slide 14]

Instances and Schemas

• Logical Schema: Overall structural design of the DB (e.g., customers and accounts in a bank). Analogous to type declarations in a program[cite: 11].
• Physical Schema: The overall physical storage layout on disk[cite: 11].
• Instance: The actual content/snapshot of data at a particular point in time. Analogous to the value of a variable[cite: 11].

Physical Data Independence

The ability to modify the physical schema (e.g., reorganize storage blocks, change indexing structures) without changing the logical schema[cite: 11]. Applications depend strictly on the logical schema and remain unaffected[cite: 11].

SLIDES 17, 18, 19 & 20

6. Database Languages (DDL, DML & Host Language Access)

Data Definition Language (DDL)

Notation for defining the database schema, integrity constraints (Primary Key, NOT NULL), and authorization permissions[cite: 11]. The DDL compiler generates table templates stored in the Data Dictionary (Metadata)[cite: 11].

Data Manipulation Language (DML)

• Procedural DML: Requires user to specify what data is needed and how to get it[cite: 11].
• Declarative (Non-procedural) DML: User specifies what data is needed without specifying how to retrieve it[cite: 11]. SQL is a declarative DML[cite: 11].

Database Access from Application Programs

SQL is NOT Turing machine equivalent (it cannot perform arbitrary general computations, display graphical windows, or communicate across network sockets)[cite: 11]. Complex operations must be written in a host language (C/C++, Java, Python) with embedded SQL queries or Application Program Interfaces (ODBC/JDBC)[cite: 11].

SLIDES 21, 22, 23 & 24

7. Database Design & Storage Manager Internals

Database Design Process

• Logical Design: Deciding the database schema. Involves a Business Decision (what attributes to record) and a Computer Science Decision (what relation schemas to have and how to distribute attributes among them)[cite: 11].
• Physical Design: Deciding the physical layout and disk data structures of the database[cite: 11].

Storage Manager Components & Data Structures

A program module providing the interface between low-level data stored on disk and application queries submitted to the system[cite: 11]:

• Authorization & Integrity Manager: Verifies integrity constraints & user permissions[cite: 11].
• Transaction Manager: Ensures consistency despite system failures and crashes[cite: 11].
• File Manager: Allocates physical block space on disk storage[cite: 11].
• Buffer Manager: Handles data caching between disk blocks and main memory (RAM)[cite: 11].
• Data Files: Store the database itself[cite: 11].
• Data Dictionary: Stores metadata about the database schema[cite: 11].
• Indices: Provide fast access to data items without scanning every record[cite: 11].
• Statistical Data: Maintained for query optimization estimation[cite: 11].

9. Database Architecture (Centralized & Shared-Memory)

• Centralized: One to a few cores with shared memory[cite: 11].
• Client-Server: Server executes work on behalf of multiple client machines[cite: 11].
• Parallel Databases: Shared memory, shared disk, or shared nothing architectures[cite: 11].
• Distributed Databases: Geographical distribution with data heterogeneity[cite: 11].

SLIDES 30 & 31

10. Two-Tier vs. Three-Tier Architectures

(a) Two-Tier Architecture

The application resides directly at the client machine, where it invokes database system functionality at the server machine across the network[cite: 11].

(b) Three-Tier Architecture

The client acts as a front end and contains no direct database calls. It communicates with an Application Server (business logic) which in turn accesses the database system[cite: 11].

11. Database Users & Database Administrator (DBA)

Database User Classes

• Naive Users: Access through pre-built forms (tellers, web users, mobile apps)[cite: 11].
• Application Programmers: Write host language applications with embedded SQL[cite: 11].
• Sophisticated Users: Analysts submitting complex ad-hoc queries through query tools[cite: 11].

Functions of a DBA

• Schema definition & storage structure / access-method definition[cite: 11].
• Schema and physical-organization modification[cite: 11].
• Granting authorization for data access[cite: 11].
• Routine maintenance, periodic backups, and disk space upgrades[cite: 11].
• Monitoring active jobs running on the database[cite: 11].
