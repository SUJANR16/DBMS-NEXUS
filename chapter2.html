SLIDES 03–06

1. Structure of Relational Databases & Unordered Tuples

• Attributes (Columns): Named property headers of a relation (e.g., ID, name, dept_name, salary).
• Tuples (Rows): Individual records stored within the relation.
• Domain: The set of allowed values for each attribute. Attribute values are normally required to be atomic (indivisible).
• The Null Value: A special value that is a member of every domain, indicating that the value is "unknown". It causes complications in the definition of many operations.
• Relations are Unordered: The physical order of tuples is completely irrelevant (tuples may be stored in an arbitrary order).

2. Database Schema, Database Instance & Key Definitions

Database Schema vs Instance

• Database Schema: The logical structure of the database.
Example Schema: instructor (ID, name, dept_name, salary)
• Database Instance: A snapshot of the data in the database at a given instant in time.

Foreign Key Constraint

A value in a referencing relation must appear in the referenced relation.
Example: dept_name in instructor references dept_name of the department table.

Superkey

Let $K \subseteq R$. $K$ is a superkey of $R$ if values for $K$ are sufficient to identify a unique tuple of each possible relation $r(R)$.
Example: {ID} and {ID, name} are both superkeys of instructor.

Candidate Key

A superkey $K$ is a candidate key if $K$ is minimal (no proper subset of $K$ is a superkey).
Example: {ID} is a candidate key for instructor.

Primary Key

One of the candidate keys selected by the database designer as the principal identifier. Primary key attributes can never be null[cite: 1].

5. Set Operations, Aggregates & Query Optimization

Set Operations ($\cup, \cap, -$) [Slides 22–26]

• Conditions: Must have the same arity and compatible domains.
• Union ($\cup$): In Fall 2017 OR Spring 2018.
• Intersection ($\cap$): In Fall 2017 AND Spring 2018.
• Difference ($-$): In Fall 2017 but NOT in Spring 2018.

Assignment ($\leftarrow$) & Rename ($\rho$) [Slides 27, 28]

• $\leftarrow$: Assigns query results to temporary relation variables.
• $\rho_x(E)$: Renames relation expression $E$ as $x$.
• $\rho_{x(A_1, \dots, A_n)}(E)$: Renames relation and its attributes.

Aggregate Functions ($\mathcal{G}$ or $\Upsilon$) [Slides 29–31]

Functions operate on multisets of values: avg, min, max, sum, count.

Basic Aggregate Example [Slide 30]: ϒ avg(salary) (instructor) ϒ count(course_id) (σ year=2018 (section))
Group By Example [Slide 31]: dept_name ϒ avg(salary) (instructor)

Equivalent Queries & Query Optimization [Slides 32, 33]

Two queries are equivalent if they produce the same result on any legal database instance:
• Rule 1: $\sigma_{\theta_1 \wedge \theta_2}(R) \equiv \sigma_{\theta_1}(\sigma_{\theta_2}(R))$
• Rule 2 (Selection Pushdown): $\sigma_{\text{dept}="Physics"}(\text{instructor} \bowtie \text{teaches}) \equiv (\sigma_{\text{dept}="Physics"}(\text{instructor})) \bowtie \text{teaches}$

1. The 6 Primitive Relational Algebra Operators:

2. Theta Join Definition:

$r \bowtie_\theta s = \sigma_\theta(r \times s)$

3. Set Intersection Derived from Difference:

$r \cap s = r - (r - s)$
